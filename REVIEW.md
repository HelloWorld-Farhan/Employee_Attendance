### Items Examined and Decided NOT to be Defects

1. **`emp_code` used as primary identifier instead of MongoDB `_id`**:
   The assignment explicitly specifies `emp_code` as the customer-defined business identifier across all endpoints and relations. MongoDB's internal `_id` is an implementation detail and should never be exposed in API requests or responses.

2. **Calendar dates and shift times stored as plain strings (`YYYY-MM-DD`, `HH:MM`)**:
   Storing dates and recurring daily shift times as strings in MongoDB is an intentional design choice described in `DATA_MODEL.md`. Converting them into epoch timestamps or ISO datetimes would bind them to arbitrary time zones and risk offset distortions.

3. **Storing precomputed derived fields (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`)**:
   `DATA_MODEL.md` explicitly mandates that derived values are computed only upon punch-in, punch-out, or manual regularization, and stored in the document. Analytics must read these stored values directly rather than recomputing them at query time.
